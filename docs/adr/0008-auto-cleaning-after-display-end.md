# 표시 종료가 지난 사용중 콜은 읽을 때 서버가 청소중으로 바꾼다

1018 고객 요청(스펙 D13·D14)으로 "종료 확인 필요"(표시 종료가 지나도 사용중으로 두고 카운터가 확인할 때까지 안내만 하는 것, 자동 완료 금지)를 이 결정으로 대체한다. 대부분의 시술은 코스 시간 안에 끝나는데, 카운터가 콜마다 손으로 종료를 눌러야 했고, 그동안 가능 판정은 표시 종료 뒤를 초과 점유로 잡았다.

원장·객실·실시간·TV 화면과 가능 판정이 그 영업일을 읽기 전에 `autoFinishOverdueCalls()`를 부른다. 실제입장이 있고 실제 종료가 없는 사용중 콜이 표시 종료를 지났으면 청소중으로 바꾸고 실제 종료 = 표시 종료로 저장한다. 상태 이력과 감사(`service_call.auto_finished`, 사유 "자동 종료")를 남기고, 행위자는 그 화면을 연 계정이다. 따로 예약 작업(cron)은 두지 않는다. 화면이 읽을 때만 바뀌므로 아무도 보지 않는 동안은 저장된 값이 사용중으로 남지만, 누가 보든 먼저 정리되므로 보이는 값과 가능 판정은 늘 같다.

- 방문완료로 바꾸지 않는다. 청소 끝은 사람이 누른다. 금액·정산 규칙은 그대로이고, 마감 확인 대상 콜(ADR 0005)이 줄어드는 것은 결과일 뿐이다.
- 입장하지 않은 예약, 실제 종료가 이미 있는 콜, 코스 길이를 모르는 콜, 잠긴 운영월은 건드리지 않는다.
- 종료 취소(청소중 → 사용중)한 적이 있는 콜은 다시 자동으로 끝내지 않는다. 손님이 아직 있다고 카운터가 정한 것이라, 다음 새로고침에 다시 청소중이 되면 안 된다. 이런 콜은 객실 화면에 지금처럼 종료확인으로 보인다.
- 쓰기는 읽은 버전(updatedAt)일 때만 하는 조건부 갱신이라, 두 화면이 동시에 읽어도 한 번만 바뀌고 이력·감사도 하나다.
- 가능 판정의 초과 점유(표시 종료부터 지금까지)와 "시술 중 종료 확인"·"앞 시술 종료 확인 필요" 안내는 없앤다. Therapist가 묶이는 끝은 실제 종료, 없으면 표시 종료다(스펙 D2).
