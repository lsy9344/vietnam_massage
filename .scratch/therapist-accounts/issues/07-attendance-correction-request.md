# 07: 출퇴근 정정 요청

**What to build:** Therapist가 근태 탭(그리고 퇴근 미입력 안내)에서 그날 출근·퇴근의 맞는 시각과 사유를 적어 정정을 요청하고, 06의 승인함에서 처리한다. 승인하면 그 시각이 "정정 승인" 방식으로 기록된다. (스펙 D23, D24, D28)

**Blocked by:** 06

**Status:** ready-for-agent

- [ ] 요청 대상은 출퇴근 시각뿐이다. 빠뜨린 출근·퇴근도 포함한다. Therapist는 출근, 퇴근 또는 둘 다의 맞는 시각과 사유(필수)를 적는다.
- [ ] 잠긴 운영월이나 마감확정 운영월의 날짜에는 요청할 수 없다. 같은 날에 대기 중인 요청이 있으면 새 요청을 거절한다.
- [ ] 승인함에서 그대로 승인하거나 사유를 적어 거절한다. 승인하는 사람이 시각을 고쳐 승인하는 기능은 없다. 다른 시각이 맞으면 거절한 뒤 기존 출퇴근 화면에서 직접 고친다(대리 입력).
- [ ] 승인하면 기존 출퇴근 서비스로 저장한다. 만근 판정과 잠금 검사를 그대로 거치고, 바뀐 쪽의 방식은 "정정 승인"이 된다.
- [ ] 승인으로 금액이 바뀌어 이미 지급 확인한 날이면 기존 규칙대로 지급 재확인 필요가 된다(ADR 0004).
- [ ] 결과와 사유는 근태 탭에 보이고, 퇴근 미입력 안내는 요청 버튼으로 이어진다. 03에서 이미 찍은 뒤 다시 누르면 나오는 안내도 이 요청으로 이어진다.
- [ ] 승인과 거절이 감사에 남는다.
- [ ] 저장할 표나 칸은 더하기만 하는 마이그레이션으로 만든다. 운영 DB 적용은 사용자 확인 뒤에 한다.
- [ ] 새 문구는 ko·vi 두 언어로 있다.
- [ ] 단위 테스트, tsc, E2E가 통과한다. E2E는 퇴근 미입력 → 요청 → 승인 → 근태 반영을 확인한다.
