# 05: 휴대폰 폭 통일과 전체 검증

**What to build:** 휴대폰 폭(600px 미만)도 흐름별 목록을 쓰고 패널을 전체 화면 시트로 연다. 기존 휴대폰 카드 목록을 대체한다. 전체 검증 뒤 프리뷰 배포를 준비한다. (스펙 D23–D25)

**Blocked by:** 04

**Status:** ready-for-agent

- [x] 600px 미만에서 같은 목록이 보이고 줄을 누르면 전체 화면 시트가 열린다. 역할별 읽기 제한(연락처·금액 등)과 빠른 예약 미제공 규칙이 그대로다.
- [x] 티켓 26 E2E를 새 목록으로 다시 쓴다.
- [x] 화면 검증: 출근 12명·하루 30콜 데이터로 1280·1024·768·390px, ko·vi에서 가로 스크롤 0, 스크린샷을 남긴다.
- [ ] `tsc`, 단위 테스트, `pnpm build`, 관련 E2E 전체가 통과한다. 기존 실패(메모리의 알려진 실패)는 기준 커밋에서 재현해 구분한다.
- [ ] 운영 DB 마이그레이션(ADR 0006, 0007)과 Cloudflare 프리뷰 배포는 사용자 확인 후에만 한다.

## Comments

- 2026-10-16: 휴대폰 카드 목록(`call-phone-card-list.tsx`)을 지우고 같은 흐름별 목록을 600px 미만에서 줄마다 세 줄 격자(시간 | 고객/메모 → 코스·매니저·객실 → 상태·경고)로 그린다. 편집 패널은 600px 미만에서 도크까지 덮는 전체 화면 시트이고, 열리면 포커스가 닫기 버튼으로, 닫기·Esc는 연 줄로 돌아간다. 휴대폰은 그대로 읽기 전용이라 입장·결제·일행 동작 버튼을 그리지 않는다(비활성 버튼 대신 없음). 빈 날짜의 "빠른 예약으로 새 콜을 만든다" 안내도 휴대폰에서는 뺀다.
- 화면 검증: 출근 12명·하루 30콜(일행 3명 포함)로 1280·1024·768·390px × ko·vi에서 목록, 완료 펼침, 패널 열림 모두 `scrollWidth - clientWidth ≤ 0`. 남은 것: vi 1024px에서 줄 끝 "Thanh toán"·"Vào phòng" 버튼 글자가 6rem 칸에서 두 줄로 접힌다(가로 스크롤은 없다, 티켓 03의 열 너비).
- 검증: tsc, 단위 896개, `pnpm build` 통과. 검증 스크립트는 기존 실패 4-6만. 관련 E2E(26·13·20, ledger-flow 02–04) 34개 통과. 전체 직렬 E2E 결과는 아래에 덧붙인다.
