# 01: 가능 코스 한 줄 목록, E코스 비활성, 코스 다시 사용·새 코스 추가

**What to build:** 빠른 예약의 가능 코스(`therapist-availability-view.tsx`)를 매니저 한 줄 목록으로 바꾼다. E코스를 마이그레이션으로 비활성화하고 기본 시드에서 뺀다. 코스 기준정보에 "다시 사용"과 "새 코스 추가"를 더한다. (스펙 D1–D9)

**Blocked by:** —

**Status:** ready-for-agent

- [x] 매니저 한 명이 한 줄이다: 이름(퇴근이면 흐린 "퇴근") · 상태(지금 가능 · 다음 예약과 여유 분 / HH:MM부터 · 다음) · 활성 코스 칩("A 60분" 형식) · 경고 아이콘. 근무표·출근 칸은 줄에서 빠진다.
- [x] 칩 문구는 코스 코드와 기준정보 시간(분)에서 만든다. 활성 코스만 나온다.
- [x] 가능 칩은 지금처럼 `onChoose`를 부른다. 불가 칩을 누르면 그 줄 아래에 불가 이유와 "경고 확인 후 배정"(있을 때만, `onOverride`)이 열린다. `onOverride`가 없으면 이유만 보인다.
- [x] 근무 확인 필요·이전 서비스 종료 확인 경고는 줄 끝 아이콘 하나이고, 누르면 문구가 펼쳐진다. 아이콘은 접근 가능한 이름과 펼침 상태를 가진다.
- [x] 정렬: 지금 가능 → 빈 시각이 이른 순 → 퇴근. 같은 묶음 안에서는 기존 순서다. 순수 함수 테스트로 확인한다.
- [x] D코스 두 번째 매니저 후보 목록도 같은 한 줄 모양이다.
- [ ] 30rem 서랍에서 가로 넘침이 없고, 출근 12명이 1280×800 화면에서 스크롤 없이 보인다(E2E 또는 스크린샷으로 확인).
- [x] 마이그레이션이 E코스를 비활성으로 바꾸고(행·정책 유지) 바뀐 건수를 로그로 남긴다. 기본 시드에서 E가 빠진다. 시드가 비활성 코스를 다시 켜지 않는다.
- [x] 코스 기준정보: 비활성 코스에 "다시 사용"이 있다. 그달 정책이 없으면 정책 입력을 함께 받는다. "새 코스 추가"는 코드(중복 거절), 이름, 시간, 가격, 2인 여부를 받는다. 둘 다 감사 기록을 남기고 관리자만 할 수 있다.
- [x] 다시 켠 코스와 새 코스가 가능 코스·빠른 예약·원장 코스 선택에 바로 나타난다(서비스 테스트).
- [x] 티켓 20·21·29·36 E2E가 새 모양에서 통과한다(`[data-availability-row]` 유지). 새 문구는 ko·vi 두 언어로 있다.

## Comments

- 2026-10-16 구현(브랜치 feat/ledger-flow-redesign).
  - 새 코스 코드: 사용자 결정으로 A–E 밖 코드도 받는다(영문 대문자·숫자 1–4자, 활성·비활성 모두 중복 거절). 정산 직원 패널의 코스별 내역, 월마감 스냅샷의 코스 구성, 대시보드 코스 비율은 A–E로 고정된 채라 새 코드는 그 칸에 따로 나오지 않는다(정산·마감 직원 합계에는 들어간다). 코드 입력 안내 문구에 적었다.
  - "그달"은 오늘(Asia/Ho_Chi_Minh)이 속한 달이다(`currentCourseMonthKey`). 화면의 기준 적용월(가장 이른 운영월)은 운영에서 이미 마감확정일 수 있어, 그 달 기준으로 정책을 받으면 잠금으로 거절된다. 다시 사용·새 코스 추가 폼의 시작월 기본값도 그달이다.
  - 근무표 표시: D1·D5대로 줄에서 근무표·출근 칸을 뺐다. 칸을 설명하던 "근무표의 근무 예정은 보장이 아닙니다" 안내도 함께 지웠고 티켓 29 E2E를 새 모양으로 고쳤다(휴무여도 칩·저장이 막히지 않는 것만 확인). 근무 예정 값은 서비스 DTO에 그대로 있다.
  - 상태 칸: 가능이면 "가능 · 다음 HH:MM · N분", 다음 예약이 없으면 "가능 · N분"(영업 끝까지 여유), 불가면 "HH:MM부터 · 다음 HH:MM". 좁은 서랍 폭 때문에 "다음 예약 없음" 글자는 넣지 않았다.
  - 칩: 가능 칩은 테두리 알약 "A 60분", 불가 칩은 ○ 기호 + 점선 테두리. 화면 낭독기 이름은 판정까지 담는다("A 60분 가능", "B 90분 · 시간 부족"). 버튼 글자가 전역 `font: inherit` 규칙 때문에 16px로 그려지는 기존 문제가 있어, 칩 글자는 안쪽 span에서 14px/600으로 정했다.
  - 상태 칩용으로 `StatusIndicator`에 `size="sm"`(12px)을 더했다.
  - 측정(운영 빌드, 1280×800, 출근 12명): 줄 하나 53px, 서랍·줄 모두 가로 넘침 0(ko·vi). 목록 전체 높이 약 636px로 한 화면 높이 안이지만, 빠른 예약 서랍의 머리(제목·설명 2줄, 두 줄로 감긴 단계 표시, 단계 제목·안내, 시각 줄, 출근 전 체크칸)가 약 430px를 차지해 서랍을 내리지 않으면 약 7명까지만 보인다. 그래서 "출근 12명이 스크롤 없이 보인다" 항목은 체크하지 않았다. 다 보이게 하려면 서랍 머리(단계 표시·설명)를 줄여야 해 이 티켓 범위(가능 코스 목록) 밖이라 사용자 결정을 기다린다.
  - 기존 동작 그대로 둔 것: 새 코스 추가 폼은 서버 거절(예: 코드 중복) 뒤 입력이 비워진다. React 19 폼 액션의 초기화이며 다른 기준정보 생성 폼도 모두 같다.
  - 마이그레이션 `20261017110000_deactivate_course_e`: 새 DB에 E·A 코스와 E 정책을 넣고 돌려 "E코스 비활성: 1건", A 그대로, 정책 행 유지, 두 번째 실행 0건을 확인했다. 운영 DB 적용은 하지 않았다(D25).
