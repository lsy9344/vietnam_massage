# 01: 가능 코스 한 줄 목록, E코스 비활성, 코스 다시 사용·새 코스 추가

**What to build:** 빠른 예약의 가능 코스(`therapist-availability-view.tsx`)를 매니저 한 줄 목록으로 바꾼다. E코스를 마이그레이션으로 비활성화하고 기본 시드에서 뺀다. 코스 기준정보에 "다시 사용"과 "새 코스 추가"를 더한다. (스펙 D1–D9)

**Blocked by:** —

**Status:** ready-for-agent

- [ ] 매니저 한 명이 한 줄이다: 이름(퇴근이면 흐린 "퇴근") · 상태(지금 가능 · 다음 예약과 여유 분 / HH:MM부터 · 다음) · 활성 코스 칩("A 60분" 형식) · 경고 아이콘. 근무표·출근 칸은 줄에서 빠진다.
- [ ] 칩 문구는 코스 코드와 기준정보 시간(분)에서 만든다. 활성 코스만 나온다.
- [ ] 가능 칩은 지금처럼 `onChoose`를 부른다. 불가 칩을 누르면 그 줄 아래에 불가 이유와 "경고 확인 후 배정"(있을 때만, `onOverride`)이 열린다. `onOverride`가 없으면 이유만 보인다.
- [ ] 근무 확인 필요·이전 서비스 종료 확인 경고는 줄 끝 아이콘 하나이고, 누르면 문구가 펼쳐진다. 아이콘은 접근 가능한 이름과 펼침 상태를 가진다.
- [ ] 정렬: 지금 가능 → 빈 시각이 이른 순 → 퇴근. 같은 묶음 안에서는 기존 순서다. 순수 함수 테스트로 확인한다.
- [ ] D코스 두 번째 매니저 후보 목록도 같은 한 줄 모양이다.
- [ ] 30rem 서랍에서 가로 넘침이 없고, 출근 12명이 1280×800 화면에서 스크롤 없이 보인다(E2E 또는 스크린샷으로 확인).
- [ ] 마이그레이션이 E코스를 비활성으로 바꾸고(행·정책 유지) 바뀐 건수를 로그로 남긴다. 기본 시드에서 E가 빠진다. 시드가 비활성 코스를 다시 켜지 않는다.
- [ ] 코스 기준정보: 비활성 코스에 "다시 사용"이 있다. 그달 정책이 없으면 정책 입력을 함께 받는다. "새 코스 추가"는 코드(중복 거절), 이름, 시간, 가격, 2인 여부를 받는다. 둘 다 감사 기록을 남기고 관리자만 할 수 있다.
- [ ] 다시 켠 코스와 새 코스가 가능 코스·빠른 예약·원장 코스 선택에 바로 나타난다(서비스 테스트).
- [ ] 티켓 20·21·29·36 E2E가 새 모양에서 통과한다(`[data-availability-row]` 유지). 새 문구는 ko·vi 두 언어로 있다.
