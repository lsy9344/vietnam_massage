# 02: 빠른 예약 일행(여러 명) 예약

**What to build:** 콜에 일행 칸(`partyId`, `partyPosition`)을 추가하는 마이그레이션과 ADR 0007을 쓴다. 빠른 예약에서 인원 수를 받아 손님마다 코스·매니저·객실을 고르고, 일행 콜 N건을 한 트랜잭션으로 만든다. (스펙 D10–D13)

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 마이그레이션은 칸 추가와 `partyId` 색인만 한다. 기존 콜은 둘 다 비어 있다. ADR 0007이 왜 별도 일행 표가 아니라 콜의 두 칸인지 남긴다.
- [ ] 고객 단계에 인원 수(기본 1)가 있다. 1이면 지금 흐름과 결과가 같다(기존 E2E 통과).
- [ ] 인원이 2 이상이면 매니저 단계에서 손님 1…N을 차례로 고른다. 손님마다 코스를 고르며 기본값은 손님 1의 코스다. 같은 매니저를 두 손님에게 고르면 막는다. D코스 손님의 두 번째 매니저 규칙은 손님마다 그대로다.
- [ ] 객실 단계에서 손님마다 객실을 고르거나 비운다. 같은 객실 중복은 기존 겹침 경고 규칙을 따른다.
- [ ] 확인 단계는 손님별 요약을 보인다.
- [ ] 저장은 콜 서비스 작업 하나이고 N건을 한 트랜잭션으로 만든다. 한 건이라도 검증에 걸리면 아무것도 만들지 않고, 오류는 해당 손님·필드 옆과 요약에 나온다. 권한·운영월 잠금·활성 여부 검사는 한 건 저장과 같다.
- [ ] 요청 id는 일행 저장 하나에 하나다. 같은 요청 id 재전송은 이미 만든 일행을 돌려준다(서비스 테스트).
- [ ] 고객 연결은 1번 콜에만, 고객/메모는 모든 콜에 같다. 각 콜에 `partyId`와 1…N `partyPosition`이 들어간다. 콜마다 생성 감사 기록이 남고 일행 id가 담긴다.
- [ ] PC·태블릿 폭 E2E: 3인 일행 저장 → 원장에 3건, 같은 시간·메모, 서로 다른 매니저. 새 문구는 ko·vi.
