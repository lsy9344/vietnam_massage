# 콜 원장 흐름 재구성: 가능 코스 한 줄 목록, 일행 예약, 흐름별 원장과 편집 패널

Status: ready-for-agent

기준일: 2026-10-16. 구현 티켓은 `issues/` 01–05다. 브랜치 `feat/ledger-flow-redesign`(워크트리 `../vietnam_massage-ledger-flow`)은 `chore/remove-earcare-bcourse-callcredit` 16aef84(귀케어·콜인정·B코스 제거, ADR 0006) 위에서 시작한다. main 병합·push는 하지 않는다.

## Problem Statement

빠른 예약의 가능 코스는 매니저마다 카드 한 장(이름, 근무표·출근·이번 시간·다음, 경고, 코스 버튼 4–5개)이라 한 사람이 4–6줄을 차지한다. 출근이 10명을 넘으면 아래로 한참 내려야 해서 전화를 받으며 한눈에 볼 수 없다.

원장은 열이 19–21개인 "전체" 보기가 기본이라 1280px 화면에서도 옆으로 넘겨야 한다. 예약 보기도 약 106rem이다. 새 콜 입력은 표 아래 별도 표라 따로 옆으로 넘긴다. 카운터는 비고, 방문별 요청, 확인값을 거의 쓰지 않는다. 콜 입력은 전화 예약 → 입장 → 결제의 세 번에 나뉘는데, 표는 매번 칸을 찾아 클릭·입력하게 하고 결제하려면 보기를 바꿔야 한다. 가장 자주 고치는 실제입장 시각도 직접 친다.

한 손님이 "3명 간다"고 연락하면 빠른 예약은 콜 한 건만 만들 수 있어 나머지 일행을 하나씩 다시 입력해야 한다. 일행이라는 사실도 어디에도 남지 않는다.

E코스(120분)는 지금 하지 않는데 활성으로 남아 있다. 기준정보에는 코스 비활성화만 있고 새 코스 추가나 다시 사용이 없어, 나중에 B·E를 다시 하려면 개발자가 손대야 한다.

## Solution

빠른 예약의 가능 코스는 매니저 한 명을 한 줄로 보인다: 이름 · 상태(지금 가능/몇 시부터 · 다음 예약) · 활성 코스 칩("A 60분", "C 90분", "D 90분"). 근무 확인·이전 서비스 종료 확인 경고는 줄 끝 아이콘으로 줄인다. 지금 가능한 매니저가 위에 온다.

원장은 하루 콜을 "지금 이용 중 / 예약 / 완료·취소" 흐름으로 묶은 한 줄 목록이 된다. 줄 끝 버튼으로 입장(지금 시각 + 빈 객실 고르기)과 결제를 처리한다. 줄을 누르면 오른쪽 편집 패널에서 예약·입장·결제·메모 묶음으로 모든 칸을 고친다. 새 콜은 빠른 예약 하나로만 만든다. 보기 전환, 표 아래 새 행 입력, 가로 스크롤은 없어진다. 휴대폰 폭도 같은 목록을 쓴다.

빠른 예약은 인원 수를 받아 사람별 코스·매니저·객실을 고르고 일행 콜 N건을 한 번에 만든다. 일행은 DB에 묶음으로 남아 원장에서 붙어 보이고, 전체 입장·전체 취소·1명 추가를 할 수 있다.

E코스는 비활성화한다. 기준정보 코스 화면에 "새 코스 추가"와 "다시 사용"을 더한다.

계산 규칙, 금액, 권한, 감사, 과거 스냅샷, 저장 무결성(요청 id, 낡은 저장 거절, 충돌 비교)은 바뀌지 않는다.

## 결정 (2026-10-16 인터뷰)

### 가능 코스 (티켓 01)

- D1. 매니저 한 명 = 한 줄. 이름 옆에는 퇴근일 때만 흐린 "퇴근"을 붙인다. 근무표·출근 칸은 줄에서 뺀다(출근 전 매니저는 기존 필터가 숨긴다). "이번 시간"과 "다음"은 상태 한 칸으로 합친다.
- D2. 코스는 코스별 칩으로 보인다("A 60분 / C 90분 / D 90분"). 활성 코스만 나온다. 칸 이름은 코스 코드와 기준정보의 시간에서 만든다. 시간으로 묶지 않는다.
- D3. 가능 칩을 누르면 지금처럼 그 매니저·코스를 고른다. 불가 칩(시간 부족, 수당 없음)도 누를 수 있고, 누르면 그 줄 아래에 불가 이유와 "경고 확인 후 배정" 버튼이 열린다(티켓 21 경로 유지).
- D4. 근무 확인 필요, 이전 서비스 종료 확인 같은 경고는 줄 끝 경고 아이콘 하나로 줄이고, 누르면 문구가 펼쳐진다. 색만으로 알리지 않는다(design.md 2.4).
- D5. D코스 두 번째 매니저 후보 목록도 같은 한 줄 모양(이름 · 상태 · 고르기)이다.
- D6. 정렬: 지금 가능 → 곧 빔(빈 시각 순) → 퇴근. 같은 묶음 안에서는 서비스가 준 기존 순서를 지킨다.
- D7. 30rem 서랍 안에서 출근 10명 이상이 스크롤 없이 한 화면에 들어가는 것을 목표로 한다.

### 코스 기준정보 (티켓 01)

- D8. E코스는 마이그레이션으로 비활성화하고 기본 시드에서 뺀다. 행과 정책은 지우지 않는다(과거 콜 금액 계산). E를 쓰는 기존 콜은 다른 코스로 바꿔야 저장된다(ADR 0006의 B와 같다).
- D9. 코스 기준정보에 "다시 사용"(비활성 코스를 다시 활성으로)과 "새 코스 추가"(코드, 이름, 시간, 가격, 2인 여부)를 더한다. 다시 사용할 때 그달에 적용되는 정책이 없으면 정책을 함께 입력하게 한다. 둘 다 감사 기록을 남긴다. 가능 코스·빠른 예약·원장 코스 선택은 활성 코스만 자동으로 보여 준다.

### 일행 예약 (티켓 02, 04)

- D10. 빠른 예약 고객 단계는 대표 고객 한 명(또는 고객 없이 고객/메모)과 인원 수(1–N)를 받는다. 시간은 일행이 공유한다. 매니저 단계에서 손님마다 매니저를 고르고, 코스는 손님마다 고르며 기본값은 첫 손님의 코스다. 객실은 손님마다 고르거나 비운다.
- D11. 저장은 콜 N건을 한 트랜잭션으로 만든다(전부 성공 또는 전부 실패). 요청 id는 일행 저장 하나에 하나다. 같은 요청 id로 다시 보내면 이미 만든 일행이 돌아온다.
- D12. 고객 연결은 대표 콜(1번)에만 한다. 고객/메모는 모든 콜에 같은 값이 들어간다. "일행 2/3" 표시는 화면이 DB 값으로 만든다(메모 글자에 덧붙이지 않는다).
- D13. 콜에 `partyId`(문자열, 비어 있을 수 있음, 색인)와 `partyPosition`(정수, 비어 있을 수 있음)을 더한다. 일행이 아닌 콜은 둘 다 비어 있다. 추가만 하는 마이그레이션이라 기존 코드와 데이터에 영향이 없다. ADR 0007에 남긴다.
- D14. 원장에서 일행은 붙어서 보인다(머리 줄 "정 대표 일행 3명" 아래 사람별 줄). 일행 전체 입장, 일행 전체 취소(확인 창), 일행에 1명 추가(같은 시간으로 빠른 예약을 미리 채워 연다)를 한다. 시간·코스·매니저·결제·노쇼는 사람별로 고친다.

### 원장 형태 (티켓 03, 05)

- D15. 보기 전환(예약 / 수납·정산 / 전체)은 없앤다. 주소의 `view` 값은 무시한다(옛 링크가 깨지지 않게 받아서 버린다).
- D16. 목록 묶음: 지금 이용 중(사용중·종료 확인·청소중) → 예약 → 완료·취소·노쇼. 묶음 안은 예약시각순. 완료 묶음은 기본으로 접혀 있고 "완료 N건"으로 펼친다. 펼친 상태는 기기에 기억한다.
- D17. 한 줄: 시간 · 고객/메모 · 코스 · 매니저1(·매니저2) · 객실 · 상태 칩과 비고 · 경고/저장 아이콘 · 다음 할 일 버튼.
- D18. "입장": 실제입장 = 지금 시각을 10분 단위로 맞춘 값, 상태 = 사용중. 객실이 비어 있으면 그 자리에서 빈 객실만 보이는 선택 목록을 연다. 잘못 누르면 패널에서 고친다.
- D19. "결제": 오른쪽 패널의 결제 묶음(결제수단 알약 현금/카드/이체/기타, 할인 구분, 계산된 결제금액)을 연다. "결제 완료"가 상태를 방문완료로 바꾼다. 관리자에게는 같은 묶음에 매니저 수당이 보인다.
- D20. 편집 패널은 칸마다 자동 저장한다. 저장 상태 표시, 낡은 저장 거절, 충돌 비교·다시 적용(티켓 15·17), 떠나기 안내(18)를 그대로 옮긴다. 방문별 요청·확인값·고객 연결 정정은 패널 맨 아래 "더 보기"에 둔다. 콜 상세 패널(경고 전체, 관련 콜)은 이 편집 패널로 합친다.
- D21. 키보드: 목록에서 ↑↓로 줄 이동, Enter로 패널 첫 칸, Esc로 목록 복귀, N으로 빠른 예약.
- D22. 새 콜은 빠른 예약으로만 만든다. 표 아래 "새 콜 행 추가"는 없앤다.
- D23. 휴대폰 폭(600px 미만)도 같은 흐름별 목록이고, 패널은 전체 화면 시트로 열린다. 기존 휴대폰 카드 목록은 이 목록으로 대체한다. 휴대폰 폭에서 빠른 예약을 제공하지 않던 규칙과 역할별 읽기 제한은 그대로다.
- D24. 완료 기준: 1280px 이상에서 원장 가로 스크롤 0. 1024px도 맞춘다.

### 진행

- D25. 티켓마다 커밋한다. 운영 DB에 마이그레이션(ADR 0006 컬럼 삭제, 0007 일행 칸 추가)을 적용하는 일과 Cloudflare 프리뷰 배포는 적용 직전에 사용자에게 다시 확인받는다. 프리뷰는 운영 DB에 붙어 있다.
- D26. 통합 워크트리(`../vietnam_massage-integration`)의 미커밋 원장 행 선택 변경은 이 작업이 대체한다. 그 변경을 하던 세션 쪽에서 원장 부분을 버릴지 확인한다. 이 브랜치는 그 변경을 가져오지 않는다.

## Out of Scope

- 객실×시간 타임라인 화면.
- 일행 단위 결제(한 번에 결제). 결제는 사람별이다.
- 방문별 요청·확인값·비고 데이터 삭제. 화면에서만 덜 보인다.
- 계산 규칙, 권한 모델, 월마감·정산 화면.
