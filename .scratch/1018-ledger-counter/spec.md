# 1018 카운터 원장 재구성: 두 줄 원장, 입장·종료·자동 청소 중, 2단계 빠른 예약, 미지명 자리

Status: ready-for-agent

기준일: 2026-10-19. 고객 원문은 `docs/plans/1018_request.md`다. 구현 티켓은 `issues/` 01–07이다. 브랜치 `feat/1018-ledger-rework`(워크트리 `../vietnam_massage-1018`)는 c99fc00 위에서 시작한다. c99fc00은 고객이 본 프리뷰 계열이고, 같은 커밋을 `backup/preview-c99fc00`에도 남겼다. main 병합과 push는 하지 않는다. `feat/1018-request-ux`(main 위 3커밋, 같은 요청을 다른 줄에서 시도한 것)는 참고만 한다.

## Problem Statement

원장 한 줄은 열 8개짜리 가로형이다. 오른쪽 패널을 열면 넘쳐서 스크롤이 생긴다. "지금 이용 중 / 예약" 묶음으로 나뉘어 있어 하루를 시간순으로 한눈에 보기 어렵다. 메신저로 연락할 때 필요한 예약 경로·예약자명 대신 고객/메모가 보인다. 객실·Therapist·상태를 바꾸려면 패널을 열어야 한다.

입장 뒤에 오는 버튼이 결제라서 실제 서비스 종료를 기록할 곳이 없다. DB에도 실제 종료 시각 칸이 없다. 표시 종료가 지나도 콜은 사용중으로 남고, 화면은 "종료 확인 필요"라는 안내만 보인다. 대부분 코스 시간 안에 끝나는데 카운터가 매번 손으로 바꿔야 한다.

빠른 예약은 5단계(고객 → 날짜·시간 → Therapist·코스 → 객실·메모 → 확인)이고, 원장을 흐리게 덮는 모달이다. 손님 문의는 "몇 시에 누가 돼요?"부터 시작한다. Therapist를 정하지 않는 미지명 예약을 자리로 잡아 둘 방법이 없다. "출근 전 보기"는 그날 근무표가 아니라 등록된 Therapist 전체를 보인다. 근무표에는 출근 예정 시각이 없다.

예약은 대부분 텔레그램·카카오톡·왓츠앱·잘로로 들어오는데, 예약 경로와 예약자명을 넣을 칸이 없다. 새 고객은 따로 만들어야 한다. 일행에 1명을 추가할 때 시각을 바꿔도 앞 일행에 그대로 붙는다.

상태별 건수는 평평한 한 줄이라 눈에 잘 안 들어온다. `1+4` 띠는 지금 받을 수 있는지와 다음 예약을 보여 주지 않는다. 하루 수납 화면에서는 카운터도 이번 달 숫자를 본다.

## Solution

원장은 예약 하나를 두 줄로 보이는 시간순 목록 하나가 된다. 윗줄은 시각 흐름·상태·주 버튼, 아랫줄은 경로·예약자·코스·Therapist·객실·결제다. 칸을 누르면 그 자리에서 고른다. 행마다 버튼은 하나이고 `입장 → 종료 → 청소 끝`으로 바뀐다. 종료를 잘못 눌렀으면 `종료 취소`로 되돌린다. 표시 종료가 지나면 서버가 실제로 청소중으로 바꾼다. 상단에는 상태 카드 7개와 Therapist 현황 줄을 둔다.

빠른 예약은 원장 옆 패널에서 열리는 2단계다. ① 날짜·시각·인원을 고르고, 맨 위 "미지명" 줄이나 Therapist 줄에서 코스를 눌러 손님을 담는다. ② 예약 경로 버튼과 예약자명을 넣고 저장한다. 미지명 예약은 Therapist를 막지 않고 그 시각의 자리만 잡는다. 자리가 모자라면 경고만 하고, 카운터가 확인하면 그대로 예약된다.

계산 규칙, 금액, 정산, 감사, 저장 무결성(요청 id, 낡은 저장 거절, 충돌 비교)은 바뀌지 않는다. 바뀌는 것은 아래 결정에 적힌 것뿐이다.

## 결정 (2026-10-19 인터뷰)

### 데이터 (티켓 01)

- D1. 마이그레이션 하나에 칸 추가만 모은다. 대상은 `service_calls.actual_end_time`(HH:MM, 비어도 됨), `service_calls.booking_channel_code`(비어도 됨), `service_calls.booker_name`(비어도 됨), `planned_working_days.planned_start_time`(HH:MM, 비어도 됨)이다. 기준정보 코드에 새 종류 `BOOKING_CHANNEL`을 더하고 기본값 7개를 넣는다(텔레그램, 카카오톡, 왓츠앱, 잘로, 전화, 워크인, 기타). 운영 DB 적용은 직전에 사용자에게 다시 확인받는다(프리뷰는 운영 DB에 붙어 있다).
- D2. Therapist가 콜에 묶이는 끝 시각은 실제 종료가 있으면 실제 종료, 없으면 표시 종료(ADR 0001)다. 청소와는 관계없다. 서비스 종료와 다음 예약 가능 사이에 버퍼는 없다.

### 원장 형태 (티켓 02)

- D3. 예약 하나를 두 줄 행으로 보이고, 예약 시각순 목록 하나로 둔다. "지금 이용 중 / 예약" 묶음은 없앤다.
  - 윗줄: 예약 시각(크게) · `입장 HH:MM → 종료` · 상태 칩 · 주 버튼
  - 아랫줄: 경로·예약자 · 코스 · Therapist ▾ · 객실 ▾ · 결제 배지 ▾
- D4. 종료 칸은 세 가지로 보인다. 입장 전에는 `미입장`이다. 종료 전에는 흐린 글씨로 `예상 HH:MM`(표시 종료)이다. 종료 뒤에는 진한 글씨로 실제 종료 시각이다.
- D5. 목록 안에 `지금 HH:MM` 구분선을 둔다. 예약 상태인데 예약 시각이 지났으면 `N분 늦음`을 붙인다.
- D6. `▾`가 붙은 칸은 누르면 그 자리에서 목록이 뜬다. 행의 나머지를 누르면 오른쪽 편집 패널이 열린다(지금처럼 비모달이고, 원장이 줄어든다).
  - Therapist 칸: 그 시각·코스에 가능한 Therapist가 위에 온다. 정렬은 지금 가능 → 오늘 완료 적은 순이다. 불가한 사람도 경고를 확인하면 고를 수 있다(기존 경고 후 배정 경로). 미지명 행에서 고르면 배정이 된다.
  - 객실 칸: 빈 객실이 먼저 온다.
  - 상태 칩: D11 규칙을 따른다.
  - 결제 배지: D12 규칙을 따른다.
- D7. 폭이 500px 안팎이어도 넘치지 않는다. 1280px·1024px에서 편집 패널이나 빠른 예약 패널을 열어도 가로 스크롤이 0이다.
- D8. 일행 행은 왼쪽 세로 막대로 묶는다. 머리 줄(일행 N · 예약자 · 전체 입장 · 1명 추가)은 지금처럼 둔다.
- D9. 방문완료·취소·노쇼는 하단 "완료·취소·노쇼 N" 접기 영역으로 간다(지금 있는 동작). 휴대폰(600px 미만)도 같은 두 줄 행을 쓰고, 지금처럼 읽기 전용이다.
- D10. 경로·예약자가 없는 옛 콜은 고객 이름을 보이고, 고객 이름도 없으면 고객/메모의 첫 줄을 보인다. 편집 패널의 입장 묶음에는 상세 시각 여섯 개를 보인다. 예약 시각·코스, 실제 입장, 예약 기준 예상 종료, 표시 종료, 실제 종료, 다음 가능 시각이다.

### 입장·종료·결제 (티켓 03)

- D11. 행 버튼과 상태 칩은 같은 규칙을 쓴다.
  - 예약 → `[입장]`: 사용중이 되고, 실제 입장 = 지금(분 단위)이다. 10분 반올림(`entryClock`)은 없앤다.
  - 사용중 → `[종료]`: 청소중이 되고, 실제 종료 = 지금이다.
  - 청소중 → `[청소 끝]`: 방문완료가 되고, 행이 하단으로 간다. 옆에 작은 글씨로 `종료 취소`를 둔다.
  - 상태 칩으로 사용중을 고르면, 입장이 비었을 때 지금으로 채우고 종료는 지운다.
  - 상태 칩으로 청소중·방문완료를 고르면, 입장이 비었을 때 예약 시각으로 채운다. 종료가 비었으면 지금과 표시 종료 중 이른 시각으로 채운다.
  - 상태 칩으로 예약을 고르면 입장과 종료를 지운다.
  - 노쇼·취소는 시각을 그대로 두고 하단으로 간다.
  - 입장·종료 시각은 누르면 그 자리에서 고칠 수 있다.
- D12. 결제 배지는 결제수단이 있으면 `결제완료`, 없으면 `결제 미확인`이다. 누르면 현금/카드/계좌/기타 목록이 뜨고, 고르는 즉시 저장된다. 상태는 바꾸지 않는다. 금액은 지금처럼 자동 계산하고, 할인은 패널에서 넣는다. 별도의 결제완료 표시값은 만들지 않는다. 이전 명세 D19(결제 완료 → 방문완료)는 이 결정으로 대체한다.
- D13. `종료 취소`는 청소중을 사용중으로 되돌리고 실제 종료를 지운다. 버튼으로 종료한 것이든 자동으로 종료된 것이든 같다. 확인 창은 없다. Therapist 가능 여부와 객실의 청소중 표시는 이 값에서 계산되므로 함께 돌아간다.
- D14. 자동 청소 중: 원장·객실·실시간·TV 화면과 가능 판정이 그 영업일 데이터를 읽을 때, 서버가 먼저 정리를 한다. 표시 종료가 지난 사용중 콜을 청소중으로 바꾸고 실제 종료 = 표시 종료로 저장한다. 감사 기록에는 "자동 종료"로 남긴다.
  - 따로 예약 작업(cron)은 두지 않는다.
  - 입장하지 않은 예약은 바꾸지 않는다. 운영월이 잠겼으면 건드리지 않는다.
  - "종료 확인 필요" 안내와 초과 점유(overrun) 계산은 없앤다.
  - ADR 0008로 남기고, `CONTEXT.md`의 용어를 고친다.
- D15. 입장이 늦어도 다음 예약을 자동으로 옮기지 않는다. ADR 0001과 기존 겹침 경고를 그대로 쓴다.

### 상단 (티켓 04)

- D16. 상태 카드 7개(전체/예약/사용중/청소중/방문완료/노쇼/취소)를 한 줄에 둔다. 전체 숫자를 가장 크게 한다. design.md의 요약 카드 토큰을 쓰고 베이지 톤을 유지한다. 누르는 동작은 지금과 같다.
- D17. Therapist 현황 줄이 `1+4` 띠를 대신한다. 상태 카드 바로 아래에 두고, 접고 펼 수 있다(기기에 기억).
  - 가로 스크롤되는 작은 카드에 다음과 같이 보인다.
    - `12번 · 완료 2 · 예약 1 · 지금 가능 · ~19:00 120분`
    - `사용 중 · 종료 예상 18:30`
    - `출근 전 · 18:00`
  - 정렬은 한 번에 하나만 고른다. 지금 가능 순(기본, 같으면 오늘 완료 적은 순), 오늘 완료 적은 순, 남은 예약 적은 순, 번호순 네 가지다.
  - 카드를 누르면 그 Therapist가 미리 고른 빠른 예약이 열린다. 카드 안의 작은 버튼은 원장을 그 Therapist의 콜만 보이게 거른다.
  - 객실과 청소 정보는 넣지 않는다. 끝에는 `미지명 N`(예약 상태이면서 Therapist가 빈 콜)을 둔다.
  - 대상은 출근 기록이 있거나 그날 근무표가 근무인 Therapist다. 퇴근한 사람은 그날 콜이 있을 때만 흐리게 보인다.
- D18. 하루 수납 화면에는 "이번 달" 숫자를 누구에게도 넣어 보내지 않는다. 오늘 숫자만 보인다. 월간 숫자는 보고·마감 화면에 그대로 남는다. (2026-10-19 고침: 처음에는 administrator·settlement_manager에게만 보냈으나, 고객 요청 10번이 "이 화면에서 이번 달을 없애라"는 것이라 관리자에게도 보내지 않는다. 운영월 누적 시재는 마감 화면(관리자·정산 담당)에서 본다. 카운터는 지금도 보고 메뉴의 월간 대시보드에서 월 매출·지출을 볼 수 있다 — 막을지는 사용자 결정 대기.)

### 빠른 예약 (티켓 05)

- D19. 편집 패널과 같은 옆 패널로 연다. 원장이 왼쪽으로 줄어든다. 휴대폰에서는 전체 화면 시트로 연다. 단계는 둘이다. 객실 단계와 확인 단계는 없다. 저장한 뒤에는 새 행이 골라진다.
- D20. ① 조건
  - 날짜·시각·인원(1–10)을 고른다.
  - 목록 맨 위에 "미지명" 줄을 두고, 그 아래에 Therapist 줄을 둔다. Therapist 줄은 이름 · 비는 시간(`~19:00 120분` / `18:30부터` / `마감까지`) · 코스 칩이다.
  - 코스 칩은 활성 코스를 같은 열에 맞춰 세운다. 줄바꿈하지 않는다.
  - 칩을 누르면 손님으로 담긴다. 미지명 줄의 칩을 누르면 미지명 손님이 된다. 비는 시간에 안 들어가는 칩은 불가로 보이고, 누르면 경고를 확인한 뒤 담긴다.
  - 그 시각에 안 되는 Therapist는 아래에 접어 둔 "N명"으로 보이고, 다음 가능 시각을 함께 보인다.
  - D코스는 기존처럼 두 번째 Therapist를 고른다.
  - 담은 손님은 하단 목록에서 뺄 수 있다. 인원만큼 담으면 `[다음]`을 누를 수 있다.
- D21. ② 고객
  - 경로 버튼(`BOOKING_CHANNEL`), 예약자명, 메모를 넣는다.
  - 예약자명을 치면 같은 이름 고객이 후보로 보인다(최근 방문 날짜). 후보를 누르면 그 고객과 연결된다. 기존 고객 검색은 그대로 쓴다.
  - 맨 아래 한 줄 요약(`18:00 · 2명 · 12번 C90, 미지명 C90 · 텔레 홍길동`)과 `[저장]`을 둔다.
  - 메모는 방문별 요청에 저장하고, 고객/메모 칸에는 예약자명을 넣는다. 그래야 객실·TV 같은 다른 화면이 지금처럼 이름을 보인다.
- D22. 저장할 때 기존 고객을 고르지 않았고 예약자명이 있으면 새 고객 기록을 만든다(이름 = 예약자명). 워크인이면서 이름이 비었으면 `워크인 N` 임시 이름을 쓰고 고객 기록은 만들지 않는다. 고객 연결은 일행의 대표 콜에만 한다(ADR 0007, 이전 명세 D12).
- D23. Therapist 목록은 출근 기록이 있는 사람이 기본이다. "출근 전 보기"를 켜면 그날 근무표가 근무인데 아직 출근하지 않은 사람을 더한다. 근무표에 없거나 휴무인 사람은 나오지 않는다.

### 미지명 자리와 출근 예정 시각 (티켓 06)

- D24. 자리 단위는 Therapist 한 명의 시간이다. 손님 1명은 1자리, D코스는 2자리다. 미지명 콜은 [예약 시각, 예약 시각+코스) 동안 자리를 잡는다. 입장 뒤에는 D2의 끝 시각을 쓴다.
- D25. 시각 t의 자리 수는 t에 일하는 Therapist 수다. 출근 기록이 있거나, 근무표가 근무이면서 출근 예정 시각이 t 이전(시각이 비었으면 종일)이고, 퇴근 전인 사람을 센다.
  - 남은 자리 = 자리 수 − t에 개인 배정 콜이 있는 Therapist 수 − t에 걸친 미지명 콜의 자리 수.
  - 새 예약은 [시각, 시각+코스) 구간 전체의 최소 남은 자리로 판단한다.
  - 지명과 미지명이 같은 남은 자리를 쓴다.
- D26. ①에 `HH:MM 남은 자리 n / N`을 보인다. 담은 손님이 남은 자리를 넘으면 경고를 보이고 `그래도 예약`을 누르게 한다. 기존 경고 후 배정과 같은 확인 창이고, 관리자 승인은 따로 없다. 지명 안내 목록은 개인 예약이 없는 Therapist를 전부 보이고 막지 않는다.
- D27. 미지명 콜에 Therapist를 배정하면 그 자리는 개인 배정으로 바뀐다. 계산은 매번 배정 유무로 다시 하므로 이중으로 빠지지 않는다.
- D28. 근무표에 출근 예정 시각을 선택 입력으로 더한다. 비어 있으면 종일 근무로 본다. 지난주 복사는 이 시각도 함께 복사한다. 출근 기록 전에는 이 시각 전을 비는 시간으로 보지 않는다(`18:00부터`). 출근 기록이 생기면 출근 기록 시각을 기준으로 한다.

### 일행 (티켓 07)

- D29. 일행은 같은 예약 시각인 콜만 묶는다. 1명 추가에서 시각을 바꾸면 일행이 아닌 별도 예약으로 저장하고, 경로와 예약자명만 이어받는다. 서버의 `nextPartyPlace`는 시각이 다른 일행 추가를 받지 않는다.

### 진행

- 조각 1은 티켓 01–04이고, 끝나면 프리뷰에 올린다. 조각 2는 티켓 05–07이고, 끝나면 프리뷰에 올린다. 프리뷰 별칭은 `app-expansion`이다.
- 프리뷰마다 운영 DB 마이그레이션과 배포를 직전에 사용자에게 확인받는다.

## 가정 (인터뷰에서 따로 묻지 않음)

- 현황 줄의 "완료"는 서비스가 끝난 콜(청소중·방문완료)이다. 이전 띠의 "한 것"(사용중 포함)과 다르다. 사용 중인 콜은 상태 칸에 보인다.
- 화면 용어는 기존 그대로 "Therapist"를 쓴다(`CONTEXT.md`).
- 예약을 바로 방문완료로 바꾸면 입장 = 예약 시각이다(D11). 시각 기록이 빠지지 않게 하려는 것이다.
