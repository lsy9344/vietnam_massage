# 03: 입장·종료·청소 끝·종료 취소, 결제 배지, 자동 청소 중

**What to build:** 행 버튼을 `입장 → 종료 → 청소 끝(+종료 취소)`으로 바꾸고, 상태 칩이 같은 시각 규칙을 따르게 한다. 결제 배지를 붙이고, 읽을 때 정리하는 자동 청소 중을 넣는다. (스펙 D11–D15)

**Blocked by:** 02

**Status:** done

- [x] 입장은 사용중으로 바꾸고 실제 입장 = 지금(분 단위)으로 저장한다. `entryClock`의 10분 반올림을 없앤다.
- [x] 종료는 청소중으로 바꾸고 실제 종료 = 지금으로 저장한다. 청소 끝은 방문완료로 바꾼다. 종료 취소는 사용중으로 되돌리고 실제 종료를 지운다. 확인 창은 없다.
- [x] 상태 칩으로 바꿀 때 D11 규칙대로 입장·종료 시각을 채우거나 지운다. 예약으로 되돌리면 둘 다 지운다.
- [x] 입장·종료 시각을 누르면 그 자리에서 고칠 수 있다.
- [x] 결제 배지는 결제수단이 있으면 `결제완료`, 없으면 `결제 미확인`이다. 누르면 수단 목록이 뜨고, 고르는 즉시 저장된다. 상태는 바꾸지 않는다. 패널의 "결제 완료 → 방문완료" 동작을 없앤다.
- [x] 자동 청소 중: 원장·객실·실시간·TV·가능 판정이 그 영업일을 읽기 전에, 표시 종료를 지난 사용중 콜을 청소중 + 실제 종료 = 표시 종료로 저장한다. 감사 기록은 "자동 종료"다. 운영월이 잠겼거나 입장이 없으면 건드리지 않는다. 같은 요청이 동시에 와도 두 번 쓰지 않는다.
- [x] "종료 확인 필요" 안내와 overrun 점유 계산을 없앤다.
- [x] ADR 0008(자동 청소 중이 "자동 완료 금지"를 대체)을 쓰고 `CONTEXT.md`를 고친다.
- [x] 객실 화면의 청소중 표시가 종료·종료 취소·청소 끝을 따라간다.
- [x] 단위 테스트(시각 규칙, 자동 정리, 점유 끝)와 E2E(버튼 흐름, 종료 취소, 자동 청소 중)를 넣는다. ko·vi 문구를 넣는다.

## Comments

- 2026-10-19 구현(브랜치 feat/1018-ledger-rework).
  - 행 버튼(`nextLedgerAction`): 예약 `입장`(사용중, 실제입장 = 지금 분 단위), 사용중 `종료`(청소중, 실제 종료 = 지금), 청소중 `청소 끝`(방문완료)과 왼쪽의 작은 `종료 취소`(사용중, 실제 종료 지움). 확인 창 없음. 지금은 영업 시간대 시계(`businessClockString`)다. `entryClock`과 10분 실제입장 목록을 지웠고, 저장 입력의 실제입장도 HH:mm이면 받는다.
  - 상태 칩은 줄의 `▾` 칸이 됐고, 칩과 패널의 상태 칸이 같은 `statusChangeTimes`(D11)를 쓴다. 오늘 원장이 아니면 "지금"을 쓰지 않는다(사용중 입장 = 예약시각, 청소중·방문완료 종료 = 표시 종료)(가정). 종료는 입장보다 이르지 않다. 입장·종료 시각은 줄에서 누르면 `type="time"` 칸이 되고, 패널의 입장 묶음에는 실제입장·실제 종료 시각 칸이 있다.
  - 결제 배지: 결제수단 목록(끝에 비우는 `결제 미확인`)이고 결제수단만 저장한다. 패널의 "결제 완료" 버튼과 줄의 "결제" 버튼(패널 결제 묶음으로 열기)을 지웠다.
  - 자동 청소 중: `autoFinishOverdueCalls()`를 원장(두 탭)·객실·실시간·TV 페이지와 가능 판정 action이 읽기 전에 부른다(읽기 서비스 안이 아니라 부르는 쪽에 둔 것은, 정산 서비스도 `listServiceCallsForDate`를 써서 읽기마다 쓰기가 섞이지 않게 하려는 것). 감사는 `service_call.auto_finished`·사유 "자동 종료", 행위자와 상태 이력 기록자는 그 화면을 연 계정이다(가정, 상태 이력이 계정 FK라). 잠긴 운영월·입장 없음·실제 종료 있음·코스 길이 모름은 건드리지 않는다. 종료 취소(청소중 → 사용중 이력)한 콜은 다시 끝내지 않는다(가정: 그렇지 않으면 다음 새로고침에 바로 다시 청소중이 된다). 읽은 updatedAt·상태·빈 실제 종료를 조건으로 고쳐 동시 읽기에도 한 번만 쓴다. 끝낼 콜이 없으면 좁은 조회 한 번으로 돌아간다.
  - 리뷰 반영: 원장 줄은 처음 받은 행만 들고 있어, 자동 청소 중이나 다른 화면이 콜을 바꾼 뒤 저장하면 낡은 저장으로 거절됐다. 보내지 않은 수정·저장 중·실패·충돌이 없는 줄은 원장이 받은 더 새 행을 따르게 했다(`call-row-save.ts`의 `refreshed`). 가능 판정 action이 콜을 끝내면 `/calls`를 다시 그린다.
  - 가능 판정의 초과 점유와 `unavailableReason`·`inServiceDisplayEnd`·`priorServiceEndCheck`, "시술 중 종료 확인"·"앞 시술 종료 확인 필요" 문구를 지웠다. 객실 화면의 `종료확인` 상태와 "앞 시술 미완료" 경고는 남겼다(종료 취소한 콜에서만 생긴다. 객실 `종료확인`은 검증 스크립트 6개와 E2E에도 걸려 있다).
  - 객실 화면은 콜 상태에서 계산하므로 종료·종료 취소·청소 끝을 그대로 따라간다(E2E로 확인).
