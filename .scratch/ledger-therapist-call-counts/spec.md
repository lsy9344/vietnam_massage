# 원장 Therapist별 한 것 +예약 수

2026-10-17 인터뷰로 정했다. 브랜치 `feat/ledger-therapist-call-counts`, `preview/dock-zone-menu` 77b2f75 위.

## 문제

정산 화면은 방문완료가 된 콜만 Therapist별로 센다. 그래서 카운터는 원장을 보면서 "누가 오늘 몇 개 했고 예약은 몇 개인지"를 알 수 없다. 예약제라 손님이 고른 Therapist로 잡는 것이 원칙이지만, 워크인 손님이나 Therapist를 가리지 않는 손님은 콜이 없는 Therapist에게 밀어 준다. 그 판단에 쓸 숫자가 필요하다.

## 결정

1. **한 것**은 사용중·청소중·방문완료 콜이고, **예약**은 예약 상태 콜이다. 노쇼·취소는 세지 않는다. 정산(방문완료만)과 달리 손님이 방에 있는 동안에는 원장 숫자가 더 크다.
2. Therapist가 둘인 콜은 두 사람에게 각자 1개다(정산과 같다). 같은 사람이 두 역할에 있으면 1개다.
3. 원장에서 고른 영업일을 따른다. 빠른 예약 카드는 서랍에서 고른 날짜를 따른다.
4. **원장 띠**: 상태별 건수 줄 바로 아래 한 줄. `한 것 +예약 │ 린 3 +2 · 마이 ▲0 +0 · …`.
   - 출근 중이면 0개여도 올린다. 퇴근했으면 그날 콜이 있을 때만 흐리게 "퇴근"을 붙여 올린다. 출근 전이면 올리지 않는다.
   - 그날 아무도 출근 입력이 없으면(내일 이후 날짜 등) 콜이 잡힌 Therapist만 올린다.
   - 순서는 Therapist 기본 순서(직원 정렬 순서)로 고정한다.
   - 출근 중인데 한 것도 예약도 0이면 ▲와 주의 색(`bg-warning-soft text-warning`)으로 감싼다. 다른 강조는 없다.
   - 끝에 "미배정 N"(예약 상태이고 첫 번째 Therapist가 빈 콜). 0이면 숨긴다.
   - 고정하지 않고 목록과 함께 올라간다. 누르는 동작은 없다. 휴대폰 폭에서는 여러 줄로 나뉜다. 하루 수납·지출 탭에는 없다.
5. **빠른 예약 카드**: 이름 옆에 같은 `3 +2`를 붙인다. 카드 높이와 카드 순서(가능 → 곧 비는 순 → 퇴근)는 그대로다. 0 강조는 띠와 같다. 두 번째 Therapist 후보 줄도 같다.
6. DB 변경 없음. 숫자는 가능 판정(`listTherapistAvailability`)이 이미 읽는 그날 콜에서 센다(`callCounts`).

## 하지 않는 것

- 띠 이름을 눌러 원장을 그 Therapist 콜로 거르기
- 콜 적은 순 정렬, "가장 적은 사람" 강조
- 정산 화면의 완료 건수 기준 변경
