# 15: 기존 행 저장 충돌 거절과 행 저장 상태

**What to build:** 원장의 기존 행을 저장할 때 화면이 마지막으로 받은 updatedAt을 함께 보낸다. 서비스는 트랜잭션 안에서 id와 updatedAt이 모두 맞을 때만 갱신하고, 맞지 않으면 STALE_CALL과 현재 행을 돌려주며 쓰기와 감사를 하지 않는다. 화면은 행마다 저장을 한 번에 하나로 제한하고, 응답을 기다리는 동안 들어온 수정은 모았다가 받은 updatedAt으로 다음 저장을 보낸다. 행마다 저장 중, 저장됨, 저장 실패, 충돌 확인 필요가 글자와 색으로 구분되어 보인다. 충돌이 나면 초안이 남고 "최신 내용으로 다시 불러오기"를 할 수 있다. 나란히 비교하는 화면은 17에서 붙인다. (스펙 B07, 스토리 37–38, 41, 43–45, 49–50, 52, V05)

**Status:** done

- [x] 같은 updatedAt으로 두 번 저장하면 하나만 성공한다. 다른 하나는 STALE_CALL과 현재 행을 받고, 쓰기와 감사 기록이 없다.
- [x] 메모리 Prisma가 id·updatedAt 조건부 갱신을 실제 DB와 같은 결과로 흉내 내고, 콜 서비스 테스트가 이를 반환값으로 확인한다.
- [x] 거절 문구는 "다른 화면에서 이 콜이 바뀌었습니다. 다시 불러온 뒤에 저장하세요."이고 두 언어로 있다. 강제 덮어쓰기 버튼은 없다.
- [x] 같은 행을 빠르게 연달아 고쳐도 자기 자동 저장끼리 충돌하지 않고 마지막 입력으로 끝난다. 늦게 온 응답이 최신 입력을 되돌리지 않는다.
- [x] 저장 상태는 운영 경고와 다른 자리에 항상 보인다.
- [x] 기존 필수 입력, 유효성, 권한, 운영월 잠금 검사가 그대로 적용된다.
- [x] 지출 저장과 고객 프로필 저장은 지금처럼 동작한다.
- [x] 두 브라우저 문맥 E2E(실제 Postgres)로 동시 저장의 거절과 초안 유지를 확인한다.

## Comments

- 2026-10-15 구현 완료(브랜치 `feat/ticket-15-stale-save-rejection`, 티켓 14 브랜치 a6b713d 위). 막는 티켓은 없지만 13·14가 고친 원장 표와 콜 서비스의 같은 자리를 고치므로 그 위에서 땄다. main 병합·push는 하지 않았다.
- 서비스: 기존 행 저장은 `expectedUpdatedAt`(화면이 마지막으로 받은 행의 updatedAt)이 필수다. `autosaveServiceCallRow()`와 `saveBasicServiceCallRow()`의 기존 행 경로가 같은 조건부 갱신(`updateServiceCallAtVersion`: id·운영월·updatedAt을 건 `updateMany` 한 번)을 쓴다. 고친 행이 없고 콜이 그 운영월에 있으면 `StaleServiceCallError`(STALE_CALL, 현재 행 포함)를 던지고 아무것도 쓰지 않는다. 필수 입력·유효성·운영월 잠금 검사는 버전 검사보다 먼저다. 메모리 Prisma는 updatedAt 조건을 보고, 고칠 때마다 updatedAt을 앞으로 옮긴다.
- 화면: 행마다 저장을 하나씩만 보낸다(`call-row-save.ts`). 응답을 기다리는 동안 입력칸은 열려 있고, 그 사이의 수정은 모았다가 응답의 updatedAt으로 다음 저장을 보낸다. 늦게 온 응답은 그 뒤에 바뀐 입력을 덮지 않는다. 저장 상태는 경고 칸이 아닌 저장상태 칸의 공통 `SaveStatus`(저장 중·저장됨·저장 실패·충돌 확인 필요)로 늘 보인다.
- 결정과 가정:
  - "최신 내용으로 다시 불러오기"는 거절 때 받은 행이 아니라 누른 순간의 행을 다시 읽는다(`getServiceCallRow`, `reloadServiceCallRowAction`). 다른 화면이 거절 뒤에 한 번 더 저장했으면 거절 때의 행은 이미 옛 값이라, 그대로 쓰면 다음 저장이 또 충돌한다(E2E에서 실제로 나왔다). 읽지 못하면 거절 때의 행으로 바꾼다.
  - 충돌 상태에서 더 고친 입력은 남지만 다시 불러오기 전에는 보내지 않는다. 비교와 다시 반영은 17에서 붙인다.
  - 마지막으로 저장된 값과 같은 초안은 보내지 않는다. 칸을 지나가기만 해도(blur) 저장하던 동작을 없앴다. 바꾼 것이 없는 저장이 updatedAt만 올려 다른 화면에 거짓 충돌을 만들고, 옛 화면에서는 충돌로 보이기 때문이다.
  - 이 화면에서 아직 고치지 않은 행도 "저장됨"과 저장 시각을 보인다(전에는 "idle" 글자가 그대로 보였다). 처음 불러온 행과 이 화면에서 저장을 마친 행은 `data-save-state`(`idle`/`saved`)로만 구분된다. E2E가 저장 완료를 기다릴 때 이것을 쓴다.
  - 저장 상태 문구가 Story 2.2의 "저장중·저장 보류"에서 디자인 시스템의 "저장 중·저장 실패"로 바뀌었다. 기존 E2E(2-2, 2-4, 2-6, client-revision)와 검증 스크립트(2-2, 2-3, 2-4, 2-6)를 새 문구와 새 파일 위치에 맞췄다. 계산 칸의 "저장 보류 계산 대기"는 그대로다.
  - 기존 행 저장의 응답을 받지 못하면(네트워크 오류) "저장 실패"와 다시 시도가 된다. "저장 여부 확인 중"은 새 행에 대해 16에서 붙인다.
  - 원장 콤보박스(SelectCell)의 blur 처리가 120ms 뒤에 그 전 값의 라벨을 다시 넣어, 그 사이에 다시 불러온 값이 옛 라벨로 보이던 문제를 고쳤다. 닫힐 때 라벨은 effect가 지금 값으로 맞춘다.
  - 충돌 상태에서 Esc는 초안을 그대로 둔다. 마지막으로 저장된 값은 이미 옛 값이라 되돌릴 곳이 아니다. 그 밖의 Esc는 전처럼 마지막 저장값(저장 중이면 보내는 중인 초안)으로 되돌린다.
