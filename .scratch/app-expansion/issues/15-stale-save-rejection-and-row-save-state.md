# 15: 기존 행 저장 충돌 거절과 행 저장 상태

**What to build:** 원장의 기존 행을 저장할 때 화면이 마지막으로 받은 updatedAt을 함께 보낸다. 서비스는 트랜잭션 안에서 id와 updatedAt이 모두 맞을 때만 갱신하고, 맞지 않으면 STALE_CALL과 현재 행을 돌려주며 쓰기와 감사를 하지 않는다. 화면은 행마다 저장을 한 번에 하나로 제한하고, 응답을 기다리는 동안 들어온 수정은 모았다가 받은 updatedAt으로 다음 저장을 보낸다. 행마다 저장 중, 저장됨, 저장 실패, 충돌 확인 필요가 글자와 색으로 구분되어 보인다. 충돌이 나면 초안이 남고 "최신 내용으로 다시 불러오기"를 할 수 있다. 나란히 비교하는 화면은 17에서 붙인다. (스펙 B07, 스토리 37–38, 41, 43–45, 49–50, 52, V05)

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 같은 updatedAt으로 두 번 저장하면 하나만 성공한다. 다른 하나는 STALE_CALL과 현재 행을 받고, 쓰기와 감사 기록이 없다.
- [ ] 메모리 Prisma가 id·updatedAt 조건부 갱신을 실제 DB와 같은 결과로 흉내 내고, 콜 서비스 테스트가 이를 반환값으로 확인한다.
- [ ] 거절 문구는 "다른 화면에서 이 콜이 바뀌었습니다. 다시 불러온 뒤에 저장하세요."이고 두 언어로 있다. 강제 덮어쓰기 버튼은 없다.
- [ ] 같은 행을 빠르게 연달아 고쳐도 자기 자동 저장끼리 충돌하지 않고 마지막 입력으로 끝난다. 늦게 온 응답이 최신 입력을 되돌리지 않는다.
- [ ] 저장 상태는 운영 경고와 다른 자리에 항상 보인다.
- [ ] 기존 필수 입력, 유효성, 권한, 운영월 잠금 검사가 그대로 적용된다.
- [ ] 지출 저장과 고객 프로필 저장은 지금처럼 동작한다.
- [ ] 두 브라우저 문맥 E2E(실제 Postgres)로 동시 저장의 거절과 초안 유지를 확인한다.
