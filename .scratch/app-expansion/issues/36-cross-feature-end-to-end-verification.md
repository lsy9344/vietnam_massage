# 36: 전체 흐름 교차 검증

**What to build:** 각 티켓에서 이미 확인한 검사를 되풀이하지 않고, 기능 사이에 남은 위험을 실제 연결로 검증한다. 중심 흐름은 전화로 고객 검색 → 빠른 예약 → 입장·객실 확인 → 완료·수납 → 지급 확인 → 마감·월 명세서다. (스펙 V01–V14, 스토리 136–142)

**Blocked by:** 01–35

**Status:** ready-for-agent

- [ ] 위 중심 흐름이 하나의 E2E로 통과한다.
- [ ] 기능이 엇갈리는 상황을 검증한다: 근무표 변경과 가능 후보, 겹친 콜과 객실 화면, 동시 저장과 응답 유실, 지급 확인 뒤 콜 정정 → 지급 재확인 필요 → 마감 거절, 재오픈 뒤 고객 연결 정정과 재확정.
- [ ] 다섯 역할이 새 서버 액션을 직접 호출해도 권한이 지켜진다. 보기 변경, 경고 상세, 겹친 콜 목록, 마감 점검이 권한을 넓히지 않는다.
- [ ] 한국어·베트남어 문구, 오류 매핑, 인쇄 문구에 빠진 키가 없다.
- [ ] PC, 태블릿, 휴대폰에서 합의한 동선, 키보드 접근, 44px 주요 조작 영역, 동작 줄이기를 확인한다.
- [ ] 데이터 이전(요청 id, 새 칸, 기존 지급완료 이전)의 적용 전후 결과, 과거 스냅샷 보존, 남는 제한을 기록한다.
- [ ] 발견한 결함은 해당 기능의 새 티켓으로 남긴다.
