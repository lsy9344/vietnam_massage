# 19: 원장 보기 전환

**What to build:** 원장 표를 예약·현장, 수납·정산, 전체 보기로 바꾼다. 같은 데이터를 다른 열 묶음으로 보여 주며, 예약시각·고객/메모·상태 열은 모든 보기에서 왼쪽에 고정된다. 드물게 쓰는 입력(확인 코드, 비고)과 경고 상세는 펼쳐서 본다. 선택한 보기는 주소에 남는다. (스펙 F02 "원장 보기", 스토리 89, 95–97, V14 일부)

**Blocked by:** 03

**Status:** done

- [x] 수납·정산 보기는 예약시각, 고객/메모, 상태, 할인, 결제수단, 결제금액, 확인 코드, 비고를 보여 주고, 권한이 있으면 수당 열도 보여 준다. 전체 보기는 모든 열을 보여 준다.

- [x] 키보드 이동 순서가 보이는 열의 순서를 따른다.

- `page.tsx`에 `.screen-tab` 모양의 보기 전환 `<nav aria-label="원장 표 보기">`를 상태별 건수 아래, 원장 표 위에 두었다(design.md 6.2 "화면 안의 보기 전환도 .screen-tab 모양을 쓴다"). 탭 전환 aria 라벨("콜 원장 보기", 기존)과 겹치지 않게 다른 문구로 정했다.
- 결정과 가정:
  - **"할인" 열의 뜻**: 수납·정산 보기 목록의 "할인"을 계산된 금액 열(`discount`, "할인")이 아니라 할인구분 선택 칸(`discountTypeCode`, "할인구분")으로 매핑했다. 수납·정산은 결제를 처리하는 보기라 할인을 실제로 적용하는 입력이 있어야 하고, 기존 E2E/코드 주석(`story-2-2`: "상태/결제수단/할인/확인값 코드는 공용 마스터 시드가 제공한다")도 할인구분·결제수단·확인값을 같은 묶음(마스터 코드 선택 칸)으로 묶어 "할인"이라 부른 전례가 있다. 계산된 할인 금액은 결제금액 칸의 취소선 표시로 이미 드러난다.
  - **"왼쪽에 고정"의 구현**: 실제 CSS `position: sticky` 가로 고정 열은 이 저장소에 전례가 없고(표에는 세로 sticky 머리만 있다) 새로 만들면 배경·테두리·z-index를 다시 다 맞춰야 해서, 세 보기 모두 "날짜 → 예약시각 → 고객/메모 → 상태"를 항상 같은 순서로 맨 앞에 두는 식으로 구현했다. 전체 보기는 기존 열 순서를 그대로 둬서(아래 항목) 이 접두 규칙을 적용하지 않았다 — 전체 보기 하나만 볼 때는 열이 전혀 움직이지 않으므로 "고정"의 취지(보기를 바꿔도 같은 자리)는 예약·현장/수납·정산 사이에서 지킨다.
  - **전체 보기는 기존 순서 그대로**: "전체 보기는 모든 열을 보여 준다"를 열 집합으로 읽고 순서는 기존(티켓 19 이전) 그대로 뒀다. 새로 보기를 고르지 않은 기본값이 전체라, 기존 E2E(`story-2-6`의 Tab/화살표 순서 단언 등)와 키보드 순서가 그대로 맞는다.
  - **수납·정산 보기엔 새 행 추가가 없다**: 이 보기엔 코스 열이 없는데 코스는 새 콜의 필수 입력이라, 그 폭으로는 새 행을 만들 수 없다. 입력 칸 대신 "새 콜은 예약·현장이나 전체 보기에서 추가하세요." 안내 한 줄만 둔다. 새 콜 만들기는 20(빠른 예약)으로 넘어가면 이 자리 자체가 없어질 수 있다.
  - **기본 보기는 전체**: 명세에 기본값이 없어, 보기 전환 이전의 동작을 그대로 보존하는 쪽(전체)을 기본으로 뒀다. `view` 매개변수가 없을 때의 `EditableCallGrid`/`CallLedgerWorkspace` 동작은 티켓 19 이전과 100% 같다(열 구성·순서·최소폭 모두).
  - **행 높이는 새로 정하지 않았다**: 보기 전환은 열 구성만 바꾸고 행 구조(`<tr className="align-top">`, 칸 높이 h-8/h-11, `py-2`)는 그대로라 PC·태블릿에서 다시 잴 필요가 없었다.
  - 경고 열("경고")은 수납·정산 보기에서 뺐다(결제 업무와 거리가 멀다). "경고 상세는 펼쳐서 본다"는 이미 콜 상세 패널(티켓 13)이 하고 있어 이 티켓에서 새로 만들지 않았다.
  - `moveTabCell`에 보기별 편집 칸 목록을 받는 네 번째 매개변수를 더했다(기본값은 기존 `EDITABLE_CALL_FIELDS`라 하위 호환). `AddRowForm`도 같은 목록으로 Tab/화살표 순서를 맞춘다.
