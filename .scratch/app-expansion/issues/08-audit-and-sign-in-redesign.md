# 08: 감사와 로그인 화면 재구성

**What to build:** 감사 화면과 로그인 화면을 01의 골격과 해당 시안을 기준으로 다시 구성한다. 동작과 권한은 바꾸지 않는다.

**Blocked by:** 02

**Status:** done

- [x] 감사 화면은 처리자, 시각, 대상, 변경 전·후, 사유를 먼저 보여 주고 원본 화면으로 이동할 수 있다.
- [x] 감사 내용을 통해 고객 연락처나 수당, 편집 권한이 새로 드러나지 않는다.
- [x] 로그인은 계정 인증만으로 권한을 정한다. 역할을 고르는 UI가 없다.
- [x] 로그인 오류는 해당 필드에 연결되고 언어 전환이 된다.
- [x] 기존 감사·로그인·권한 E2E가 통과한다. 두 언어를 확인한다.

## Comments

- 2026-10-15 구현 완료(`feat/ticket-08-audit-sign-in`, 기준 2f3f5ce). 동작과 권한은 그대로다. main 작업 트리에 05가 커밋되지 않은 채 있어 06·07처럼 별도 브랜치로 했다.
- 감사: 설정 › 감사의 기간·대상 필터 → 기록 표(시각, 처리자, 대상, 변경 전·후, 사유) → 고른 기록의 변경 상세 비모달 패널(주소 `?log=`). 패널은 처리자·시각·대상·작업·사유, 원본 화면 링크, 항목별 변경 전·후 표(바뀐 항목에 ◆ 바뀜, 객체 항목은 한 단계 펼침), 원본 JSON 순이다. 처리자는 계정 내부 id 대신 직원 표시 이름과 계정 ID로 보인다(`listAuditActors`). 원본 화면 링크는 `canAccessRoute`를 통과할 때만 그린다. 날짜 오류는 해당 칸에 `aria-describedby`로 연결한다. 재오픈처럼 사유를 변경 후 값에 담은 기록도 사유 칸에 보인다.
- 원본 화면 링크는 그 화면과 운영월·날짜(콜·지출·출근·마감), 고객(`visitCustomer`)까지 연다. 기준정보는 탭만 연다. 07의 `?item=`과 05의 `?employee=`가 main에 들어오면 그 항목까지 열 수 있다.
- 로그인: 셸 없는 가운데 카드(24px, `--surface`), 머리말의 골드 표식과 언어 전환, 검정 주 버튼. 입력칸은 이메일·계정 ID와 비밀번호 둘뿐이다. 빈 칸 오류는 칸 아래에, 계정 정보 거절은 두 칸이 같은 문장을 가리킨다. 오류를 번역 key로 들고 있어 오류가 보이는 중에 언어를 바꾸면 새 언어로 다시 그려진다(브라우저 기본 required 말풍선은 끔).
- 감사 E2E를 패널 구조로 고쳤다(1-3, 1-4, 1-5, 1-8, `tests/e2e/support/audit.ts`). 검사 스크립트 1-3은 페이지와 작업면 파일을 함께 읽는다.
