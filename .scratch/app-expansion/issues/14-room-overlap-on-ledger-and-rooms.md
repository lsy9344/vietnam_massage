# 14: 객실 겹침: 원장 경고와 객실 화면

**What to build:** 같은 날 같은 객실에서 [예약시각, 예약시각 + 코스 길이) 구간이 겹치면 양쪽 콜에 "이 객실에 {상대 예약시각} 콜이 있습니다"를 붙인다. 행 문장에는 가장 이른 상대 하나를 쓰고, 상대 콜 id 전체를 함께 반환한다. 객실 화면은 같은 판정 결과를 받아 "겹친 콜 N건"과 펼쳐 볼 수 있는 관련 콜 목록을 보여 준다. (스펙 B06과 "객실·실시간·TV", 스토리 23–26, 31–34, V04)

**Blocked by:** 04, 13

**Status:** done

- [x] 같은 객실의 14:00–15:30과 15:00–16:00은 양쪽에 상대 예약시각이 붙는다. 15:00에 끝나는 콜과 15:00에 시작하는 콜은 겹치지 않는다. 세 콜이 겹치면 행에는 가장 이른 상대와 나머지 건수가 나온다.
- [x] 노쇼, 취소, 객실이 없는 콜은 빠진다. 실제입장과 표시 종료는 쓰지 않는다. 저장은 되고 어느 쪽 예약시각도 밀지 않는다.
- [x] 객실 상태 서비스는 콜 서비스가 반환한 겹침 결과를 그대로 소비하며 다시 판정하지 않는다. 소비자 테스트로 확인한다.
- [x] 관련 콜 항목에는 예약시각, 코스, Therapist, 상태, 표시 종료만 있고, 고객/메모·연락처·금액·수당은 없다.
- [x] 관리자와 카운터는 각 항목에서 원장의 콜 상세로 이동한다. 웨이터와 조회 전용 사용자에게는 링크가 없다.
- [x] 실시간과 TV에는 겹침 목록이나 원장 경고 문장이 들어가지 않는다. 표시 종료는 바뀌지 않는다.
- [x] 실시간 카드에서 관리자와 카운터는 원장의 그 콜 상세로 이동한다. (스토리 146)
- [x] 웨이터로 로그인한 E2E로 링크와 고객 정보가 없음을 확인한다. 새 문구는 두 언어로 있다.

## Comments

- 2026-10-15 구현 완료(브랜치 `feat/ticket-14-room-overlap`, 티켓 13 브랜치 1155500 위). 13이 main에 없어 그 위에서 땄다. main 병합·push는 하지 않았다.
- 서비스: 판정은 `roomOverlapFor`(콜 서비스) 하나다. 원장 행은 `room_overlap { relatedTime: 가장 이른 상대의 예약시각, relatedCallIds: 상대 전체(이른 순) }`를 받고, 객실 상태 서비스는 `roomFloorFactsForDate()`의 `roomOverlaps`(영업일 예약시각 순)를 그대로 받아 `overlappingCalls`를 채운다. 표시 종료와 같은 한 번의 읽기로 판정한다. `displayEndInstantsForDate`는 E2E 3-1이 써서 남겼다.
- 가정: 운영월에 유효한 코스 정책이 없는 콜은 길이를 몰라 겹침에서 빠진다(가능 코스 점유도 같은 규칙). 방문완료와 청소중은 겹침에 든다(스펙이 빼는 것은 노쇼·취소·객실 없음뿐). "겹친 콜 N건"의 N은 그 객실에서 겹침 상대가 있는 콜의 수다. 대표 콜이 없는 빈방이라도 방문완료끼리 겹쳤으면 목록이 붙는다(원장과 같은 결과).
- 문장: 객실 겹침은 원장의 예약시각 그대로 "이 객실에 14:00 콜이 있습니다"라고 말한다(13의 양보 문장처럼 12시간제로 바꾸면 01:00 슬롯과 헷갈린다). 상대가 여럿이면 "… 외 N건"이 붙고, 다른 경고 수는 지금처럼 "+N"이다.
- 화면: 객실 화면만 `includeOverlaps`를 켠다. 실시간과 TV는 예전과 같은 질의만 한다. 실시간 카드의 원장 링크는 대표 콜로 간다(스토리 146).
- 확인: 단위 598건, tsc, 검증 스크립트(4.6은 13 기준 커밋에서도 실패하는 기존 문제), 13·14 E2E 13건 통과.
