## Comments

- 2026-10-15 구현 완료(브랜치 `feat/ticket-07-master-data`, 기준 2f3f5ce). 입력 항목·규칙·권한은 그대로이고 화면만 바꿨다.
- 운영월·객실·코드·시간·직원·코스·수당: 읽기 전용 목록 + 행을 고르면 열리는 비모달 편집 패널(정보구조 9절). 고른 항목은 주소 `?item=`에 남고, 키보드로 고르면 포커스가 패널로 간다. 공통 부품은 `src/app/(erp)/masters/master-{parts,fields,workspace,view-model}`.
- 화면 맨 위에 활성·비활성 수(운영월은 단계별 수), 목록에서 활성 여부는 이름 바로 다음 열이고, 비활성 행에는 "지우지 않고 남겨 둔 …" 설명이 붙는다. 패널은 편집 칸보다 변경 영향을 먼저 보인다. 변경 영향 문장은 서비스 동작을 확인해 썼다(예: 객실·TV 판은 정렬 순서가 아니라 표시명 앞 숫자로 순서를 정한다, 시스템 기본 코드의 표시명은 다른 화면에 쓰이지 않는다, 직원 비활성은 출근·정산 명단에서도 빠지고 연결 계정은 막지 않는다, 새 정책 이력은 기간이 겹치면 거절된다).
- 생성은 서랍(운영월·직원은 도구줄 주요 행동, 코드·시간 슬롯·운영팀 인센 규칙은 구역 보조 버튼), 편집은 패널. 데이터 계약에 없는 객실 추가, 적용월 선택, 직원 직군 탭·검색, 재활성화는 넣지 않았다.
- 코스·수당: 코스 목록, 마사지사 × 코스 수당 표(칸을 고르면 패널, 0원과 미등록을 다르게 보임), 일·월 인센 규칙 목록. 기준 적용월은 기존대로 가장 이른 운영월이다(스토리 1.8).
- 시트 매핑: 요약 카드 4장, 숨김 목록 gate, 검증 표 머리글 두 언어, 열린 추적은 목록 + 이슈 상세 패널(상태·메모 저장은 패널 안, 조회 전용은 읽기만).
- 두 언어: 주/야간·재직상태 값은 한국어 stable key 그대로 두고 보이는 이름만 번역했다.
- E2E: 기존 기준정보 스펙(1-4~1-8, 7-1, 7-3)을 행 → 패널, 생성 → 서랍 구조에 맞췄다(검증 동작은 그대로). 검사 스크립트 1-5·1-8의 E2E 문자열 검사를 새 구조에 맞췄다. 7-3 브라우저 테스트는 `PLAYWRIGHT_SKIP_WEBSERVER=1`이면 늘 건너뛰어 왔는데, 켜서 돌려 보니 "조회 전용" 글자가 도크의 나 메뉴(티켓 02)에도 있어 본문으로 범위를 좁혔다. 새 스펙 `story-ticket-07-master-screens`(주소로 패널 복원, 비활성 설명, 키보드 포커스 이동과 복귀, 44px, ko·vi × 1440·1024·390px 문서 가로 넘침 0).
- 확인: 타입 검사, 단위 테스트 464개, 검사 스크립트(기존 실패 4-6 하나), 기준정보 E2E 50개 통과. 운영 빌드 전체 E2E 직렬(새 DB, 리뷰 반영 전): 232 통과, 실패 5개는 모두 메모의 기존 문제(2-1:285, 2-5:270, 5-3:173·242, 5-5:210).
- 남긴 것: (1) 패널 안 저장은 보조 버튼이다(design.md 6.3 "패널의 저장"은 주 버튼이지만 패널마다 저장 폼이 여럿이고 "주 버튼은 화면마다 하나"와 부딪힌다). (2) 시트 매핑 요약 카드 4장은 모두 민트다(보존율·건수에 맞는 파스텔 계열이 design.md 2.3에 없다).
