# 01: UI/UX 리서치: 업무 흐름 중심 정보구조와 화면 골격

**What to build:** 모든 화면을 다시 구성하기 전에, 다섯 역할(관리자·카운터·정산 담당·웨이터·조회 전용)이 실제로 하는 업무 흐름을 기준으로 앱 전체의 정보구조, 화면 사이를 오가는 방식, 화면별 골격을 정해 문서로 남긴다. 흔한 좌측 사이드바 + 상단바 구성은 쓰지 않는다. 기능이 바뀌지 않는 화면(대시보드, 리포트, 기준정보, 감사, 로그인, 실시간, TV)도 대상에 넣는다. 이 결과가 뒤의 모든 화면 재구성 티켓의 기준이 된다. 색과 글꼴 토큰은 지금 브랜드의 Royal Gold로 정해져 있다. UI 재구성 가이드, 화면별 시안 27장, Royal Gold 개선 5장은 화면 안의 정보 위계를 정할 때 참고하는 자료이며, 시안의 사이드바·상단바 배치는 따르지 않는다. (스펙 F08과 "언어, 디자인, 기기", 스토리 136–142)

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 지금의 모든 라우트를 역할별 접근 범위와 함께 정리하고, 각 화면이 어떤 업무 흐름의 어느 단계인지 적는다.
- [x] 역할별 하루 업무 흐름을 단계와 화면으로 그린다. 최소한 전화 예약, 입장·객실 확인, 완료·수납, 출퇴근 정정, 지급 확인, 마감, 기준정보 관리, 현장 조회를 포함한다.
- [x] 업무 흐름 중심의 탐색 방식을 믿을 만한 1차 자료(공개 디자인 시스템, 접근성 기준, 현장 POS·예약 시스템 사례)로 조사하고 출처를 단다. 경쟁사 조사 문서는 참고만 한다.
- [x] 탐색 방식 후보를 둘 이상 비교하고 하나를 고른 이유를 적는다. 좌측 사이드바 + 상단바는 후보에서 뺀다.
- [x] PC, 태블릿, 휴대폰, TV에서 탐색과 화면 골격이 어떻게 달라지는지 정한다. 기기에 따라 권한이 달라지지 않는다.
- [x] 모든 화면의 골격을 정한다: 첫 화면에 보일 것, 주요 행동 하나, 요약, 본문, 그리고 탭·패널·별도 화면 중 무엇으로 나눌지. 스펙의 콜 원장 화면 분리 기준과 어긋나지 않는다.
- [x] 공통 컴포넌트 목록과 각각의 쓰임을 정한다: 상태 표시, 경고, 저장 상태, 패널·서랍, 탭, 표, 카드, 확인 다이얼로그, 그리고 로딩·빈 상태·오류·잠금·갱신 지연 상태.
- [x] 결과를 저장소의 디자인 문서로 남기고, 기존 UI 재구성 가이드 중 이 결과로 대체되는 부분(탐색 셸, 시안의 사이드바·상단바)을 그 문서에 명시한다.
- [x] 업무 규칙, 계산, 권한은 바꾸지 않는다. 필요하면 핵심 흐름(전화 예약, 마감)을 버리는 시제품으로 확인할 수 있지만 제품 코드는 바꾸지 않는다.
