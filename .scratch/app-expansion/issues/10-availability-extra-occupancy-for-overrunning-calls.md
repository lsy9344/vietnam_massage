# 10: 가능 코스: 끝나지 않은 시술의 추가 점유

**What to build:** 고른 서비스 날짜가 오늘이고 사용중인 콜이 표시 종료를 지났다면, [표시 종료, 지금) 구간을 그 Therapist의 추가 점유로 보아 가능 코스에서 불가로 보이게 한다. 사유는 "시술 중 · {표시 종료} 종료 확인", 비는 시각은 지금이다. 그런 Therapist의 가능 후보에는 "시간표상 가능 · 앞 시술 종료 확인 필요"를 붙인다. 가능 코스 판정은 지금 시각을 입력으로 받고, 입력이 없으면 서버 시각을 쓴다. (스펙 B01, F02 일부, ADR 0001, 스토리 1–4, 11, V01)

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 오늘 14:00 시작, 60분, 다음 예약 없음, 사용중, 지금 15:20이면 15:00은 불가(15:00 종료 확인, 비는 시각 15:20)이고, 15:30은 가능이면서 "앞 시술 종료 확인 필요"가 붙는다.
- [x] 같은 콜이 예약 상태이거나 고른 날짜가 어제면 추가 점유가 없다. 청소중·방문완료·노쇼·취소도 추가 점유가 없다. 지금이 표시 종료보다 이르거나 같으면 추가 점유가 없다.
- [x] 기존 점유와 추가 점유 중 하나라도 고른 시각을 덮으면 불가이고, 비는 시각은 두 구간의 끝 중 늦은 시각이다.
- [x] Therapist 1과 Therapist 2 배정을 모두 같은 사람의 점유로 센다.
- [x] 추가 점유는 표시 종료, 뒤 콜의 예약시각, 코스, 금액을 바꾸지 않는다.
- [x] 판정 결과는 안정적인 코드와 시각으로 반환하고, 문장은 화면이 두 언어 메시지 키로 만든다. 화면은 점유를 다시 계산하지 않는다.
- [x] 콜 서비스 테스트가 위 예시와 경계를 반환값으로 확인하고, 뷰 테스트가 문장과 시각을 그리는지 확인한다.

## Comments

- 2026-10-15 구현 완료(`feat/ticket-10-availability-overrun`, 기준 260a0c1). `listTherapistAvailability`가 `now`를 받고(없으면 서버 시각), 행에 `unavailableReason`(`booked` / `in_service_past_display_end`), `inServiceDisplayEnd`, `priorServiceEndCheck`를 더해 돌려준다. 표시 종료는 원장과 같은 `displayEndChoice`로 구한다.
- 2026-10-15 사용자 결정: "고른 서비스 날짜가 오늘"의 오늘은 달력날이 아니라 지금이 들어 있는 영업일이다(첫 활성 슬롯부터 다음 날 첫 슬롯 전까지). 달력날로 두면 23:00 콜(표시 종료 00:00)이나 00:30에 전날 날짜를 볼 때 추가 점유가 생기지 않는다. 스펙 공통 원칙 문장을 함께 고쳤다.
- 추가 점유만으로 불가여도 바로 뒤에 맞닿은 예약이 있으면 비는 시각은 그 예약의 끝이다("두 구간의 끝 중 늦은 시각"). 사유는 시술 중으로 남는다. 같은 Therapist의 추가 점유가 겹치면 가장 이른 표시 종료를 말한다. 빈 분은 고른 시각 뒤에 시작하는 추가 점유까지만 센다(실제입장이 늦어 표시 종료가 예약 끝보다 뒤인 경우). 다음 예약 칸은 예약 점유만 본다.
- 화면: "시간표상 가능 · 앞 시술 종료 확인 필요"는 행마다 한 번 경고 칩으로 그리고 가능 코스 버튼마다 `aria-describedby`로 잇는다. 사용자 요청으로 가능 코스 영역을 design.md에 맞췄다(18px 카드, 6.6 표, 6.4 입력칸, 알약 버튼, 상태·경고 칩). 이 영역은 티켓 20에서 빠른 예약 패널로 옮겨진다.
