# 30: 지급 확인 기반과 Therapist 일별 행

**What to build:** 새 지급 확인 서비스를 두고, 확인·재확인·해제를 금액·처리자·시각·사유가 있는 사건으로 쌓는다. 현재 상태(미확인, 확인됨, 지급 재확인 필요, 확인 금액 미기록)는 사건과 현재 계산 금액에서 도출한다. 현재 계산 금액은 기존 계산 서비스의 결과를 그대로 쓰고 계산식은 바꾸지 않는다. Therapist 일별 정산 행의 지급완료 표시를 이 지급 확인으로 바꾸고, 기존 지급완료 기록과 이력은 금액 없는 확인 사건으로 옮긴다. 귀케어와 운영팀은 31에서 붙인다. (스펙 F05, ADR 0004, 스토리 110–117, 122–123, V08)

**Blocked by:** 05

**Status:** ready-for-agent

- [ ] Therapist 일별 계산 결과가 이 작업 전과 같다.
- [ ] 확인 당시의 금액, 시각, 처리자가 기록된다.
- [ ] 확인 뒤 출퇴근이나 완료 콜이 정정되어 금액이 달라지면 지급 재확인 필요와 함께 이전 금액, 현재 금액, 차이가 나온다.
- [ ] 사유를 적고 재확인하면 현재 금액이 새 기준이 되고 표시가 사라지며, 이전 확인 기록은 남는다. 이후 금액이 또 바뀌면 다시 지급 재확인 필요가 된다.
- [ ] 재확인과 해제에는 사유가 필수다.
- [ ] 옮겨진 기존 지급완료는 "확인 금액 미기록"으로 보이고, 운영월이 작성중이나 검토중이면 지급 재확인 필요로 센다. 과거 확인 금액을 현재 계산값으로 채우지 않는다. 마이그레이션 전후 건수를 기록한다.
- [ ] 마감확정이나 잠금 운영월에서는 사건을 쓸 수 없다. 기존 지급 잠금 검사를 쓴다.
- [ ] 각 행에 계산 금액, 확인 상태, 마지막 확인 금액, 차이, 확인 이력 보기가 있다. 지급 확인이 송금처럼 보이지 않는다.
- [ ] 관리자와 정산 담당만 쓸 수 있고, 다른 역할이 서버 액션을 직접 호출하면 거절된다.
- [ ] 지급 확인 서비스 테스트(메모리 Prisma)와 E2E로 확인한다. 새 문구는 두 언어로 있다.
