# app-expansion 리뷰 후속 수정·검증 (2026-10-16)

대상: `fix/app-expansion-code-review`, 기존 S1–S12·T1·T2 위에서 T3–T8 및 티켓 37–39를 마무리했다. 통합 대상은 `integration/app-expansion`이다. main 병합과 push는 하지 않는다.

## 사용자 결정

- 기존 콜의 고객 칸은 상세 패널의 사유 필수 정정으로 연결한다. 새 콜 생성 때 고객을 고르는 동작은 유지한다(37).
- 근무표는 정산 구역 첫 탭으로 옮긴다. 도크는 날짜·운영월을 유지하는 기존 Therapist 정산 진입점을 사용한다.
- 날짜·운영월 변경에도 미저장 입력 안내를 유지한다(18).
- 빠른 예약의 “지금”은 Therapist 단계로 바로 이동한다(20).

## 변경

- T3: 근무 예정 값·읽기 조회를 masters의 독립 조회 파일로 분리했다. 직원 비활성의 콜 조회도 calls의 독립 조회로 분리했다. 월 명세서는 정산과 마감 스냅샷을 조합하는 closing 모듈로 옮겼다. 도메인 서비스 41개 런타임 import 그래프에서 순환이 없음을 확인했다.
- T4: 근무표 E2E는 전용 직원·날짜와 처리자별 감사 건수로 한정했다. 이번 확장 스펙이 실제 시드한 직원 id를 추적해 종료 시 비활성화하고, 정렬 순서 충돌을 피한다. 티켓 15·16·17의 운영월을 분리하고 09의 과거 콜을 서비스 날짜 기준으로 맞췄다.
- T5: 지급 확인·마감 입력칸을 공용 입력 토큰으로, 빠른 예약 오류를 ScreenState로 바꾸고 단계 글자를 최소 12px로 맞췄다.
- T6: 고객 후보 비교는 목록상자가 직접 소유하는 선택 항목으로 만들고, 목록별 고유 id·aria-activedescendant·방향키/Enter 선택·포커스 링을 연결했다.
- T7: calls/settlements/closing README를 갱신하고 원장 주소 함수를 `src/lib/ledger-address.ts`로 옮겼다. 모호한 “시간 겹침” 대신 시간표상 가능 조건을 설명한다.
- T8: 네 정산 계산기의 지급 확인 연결, Therapist 지급 패널, 귀케어·운영팀 출근 오류 매핑을 공유한다.
- 37: 기존 행의 일반 저장으로 고객 연결을 바꿀 수 없도록 서버에서도 거절한다. 정정은 기존 잠금·버전 검사와 사유 포함 감사를 사용한다.
- 38: 이미 저장된 빠른 예약 안내가 패널 밖에 남는다. 일반 성공에는 표시하지 않으며 새로 패널을 열 때 지운다.
- 39: 마감 처리 네 버튼을 공용 44px Button으로 바꿨다.

## 검증

- 타입 검사 통과.
- 단위 테스트 **884/884 통과**(이전 리뷰 수정 포함).
- 운영 빌드 통과.
- 스토리 검증 스크립트를 모두 실행했다. **4-6만 기존 문자열 검사 실패**: `service-call-service.ts`에 `serviceDate: {`를 요구한다. T3에서 독립 콜 조회를 분리하면서 우연한 문자열 일치가 사라졌다. 5-2의 이동된 기준 상수 검사는 실제 상수 파일을 읽도록 수정했다.
- 전체 E2E **333개, workers=2**: 277 passed, 23 failed, 33 skipped/did-not-run (`e2e-full/results.json`). 기존 330개에 리뷰 단계와 이번 후속 작업의 3개가 추가됐다.
- 실패 스펙 21개를 **새 DB, workers=1**로 재실행: 75 passed, 9 failed, 8 skipped/did-not-run (`e2e-failed-serial/results.json`). 제품 동작·고정 데이터에 맞게 선택자와 시드를 수정한 뒤에는 아래 기존 실패 6개와 선택자 3개가 남았다.
- 선택자 3개를 수정한 후 저장 충돌 비교 2개·고객 비교 2개가 통과했다 (`e2e-corrected/results.json`). 같은 실행의 기존 PC 예약 케이스는 서버 저장 뒤 원장 행 갱신이 늦어 실패했고 뒤 예약 케이스들이 건너뛰어졌다. 이 PC 케이스는 앞선 전체/직렬 실행에서는 통과했다.
- 마지막으로 **새 DB**에서 응답 유실 후 빠른 예약 재시도·안내·저장 행 포커스와 키보드 전체 조작·확인 후 원래 버튼 포커스 복귀를 따로 실행해 **2/2 통과**했다 (`e2e-booking-focused/results.json`).
- 첫 전체 실행에서 고객 연결 정정(25) 3개, 근무표(27) 5개, 교차 업무 흐름(36) 3개가 모두 통과했다. 월 명세서(32)와 마감 점검·예외 마감·재오픈(33–35) 스펙도 첫 전체 실행에서 통과했다.

## 실행·증거

`bash .scratch/app-expansion/validation/run-e2e.sh <workers> <run-name> [스펙/옵션]`을 운영 빌드 후 실행한다. 전용 DB `vietnam_aesthetic_trf`, 포트 3180을 사용한다. 로컬 .env가 테스트 DB 주소를 바꾸지 않도록 CI 환경을 적용하고 재시도는 0으로 고정한다. 실행마다 새 DB이며 다른 연결이 있으면 DROP을 거절한다. 종료 시 확인한 서버 PID만 끈다.

실행별 JSON·출력·서버 로그와 baseline/final 단위·빌드 로그는 이 validation 폴더의 ignored 하위 폴더에 보존한다. 스크립트와 이 요약은 커밋한다.

## 정리
